This week, I worked on preparing various areas of the project for my upcoming playable rope dart demo and started working on pixel art for the first time! 


### Project Management

Building off of last week’s progress on setting up my GitHub Projects workspace, I spent a few hours at the start of this week creating a preliminary backlog of high-level tasks. Since I had only recently decided to change the scope and focus of the game, creating this list of tasks also helped clarify a lot of ideas in my mind and give a better picture of what the game will actually look like. Going forward, this backlog will help me better keep track of my overall progress, as well as give me easily identifiable tasks to work on at the start of each sprint. 


### Interaction Design & Workflow

With the deadline for a playable rope dart demo only a week away, I (finally) began creating a comprehensive list of all of the actions the player can perform with the rope dart. With the new back-end graph structure I created last week, this meant coming up with a list of actions and how they can be connected and chained together. 

I started out creating this list directly in my Unity project in a JSON format, but quickly got annoyed with having to constantly scroll up and down the large file and ensure all of my strings matched exactly. So to make editing easier, I have switched to using Google Sheets for my main design software, and I could not be happier. The data is far more condensed, and the ability to use data validation rules, dropdown cells, and checkboxes make avoiding typos so much easier. 

<img src="/images/2026-07-19-google-sheet.png">

To import the data into Unity, I created a custom importer tool that takes a CSV file from Google Sheets and translates the data into a JSON file, which can then be read by the game at runtime. As an extra quality-of-life feature for myself, I used the HttpClient class from System.Net.Http to use a direct export link from the spreadsheet, so I don’t have to keep exporting and re-importing the file every time I make a change. 


### Intro to Pixel Art

While I’ve gotten used to testing the rope dart while staring at a bunch of colorful circles and a rotating rectangle, I want this upcoming demo to be a bit more intuitive for playtesters. So, I’ve started creating basic pixel art stick-figures representing the key motions for the various actions listed in the aforementioned Google Sheet. I’m still getting used to working in Aseprite and with pixel art in general so it’s unlikely that the demo will contain anything much more fleshed out, but it should at least get the idea across. This is the area of the project that I have the least prior experience in, so I’m trying to be patient with myself and focus on learning over results for now! 


### Coming Up

I have committed to sharing a playable rope dart demo by next Sunday, so next week’s work will be entirely dedicated to preparing that demo. With most of the design done for now, I’ll be continuing my pixel art stick figures and cleaning up some outdated rope dart logic to account for sprite animations. 

That’s all for this week, thanks for reading!
